# Теоретическая база прототипа Machine Unlearning

> Проект 2039 «Механизмы цифрового забвения», МИЭМ НИУ ВШЭ, ТК 26.
> Документ описывает, как в прототипе устроены этапы **обучения**,
> **удаления данных (unlearning)**, **сбора метрик** и **оценки
> эффективности**, и даёт ссылки на первоисточники.

## 1. Постановка задачи

Имеется обучающий набор $D = \{(x_i, y_i)\}_{i=1}^N$ и алгоритм обучения
$\mathcal{A}$, который по $D$ строит модель $\mathcal{A}(D) = h$.

Пусть пользователь подал запрос на удаление подмножества $D_f \subset D$
(«forget set»). Корректная процедура «машинного разобучения»
$\mathcal{U}$ должна удовлетворять:

$$
\mathcal{U}(\mathcal{A}(D),\, D_f,\, D) \;\overset{d}{\approx}\; \mathcal{A}(D \setminus D_f),
$$

то есть её выход статистически неотличим от модели, обученной с нуля на
«очищенном» наборе $D \setminus D_f$. Формализация в терминах
дифференциальной приватности даёт понятие **$(\varepsilon, \delta)$-certified
unlearning** (Guo et al., 2020).

Для прототипа мы реализуем **exact unlearning через архитектуру SISA**
(Bourtoule et al., 2021): равенство распределений достигается
конструктивно — за счёт изоляции обучения и переобучения только
затронутых шардов.

## 2. Архитектура системы (SISA)

```
┌─────────────────────────────────────────────────────┐
│                датасет D (N строк)                  │
└──────────────┬──────────────────────────────────────┘
               │ hash(user_id, seed) mod S
               ▼
  ┌───────┐ ┌───────┐ ┌───────┐ ... ┌───────┐
  │shard 0│ │shard 1│ │shard 2│     │shard S│  ← disjoint
  └───┬───┘ └───┬───┘ └───┬───┘     └───┬───┘
      ▼         ▼         ▼             ▼
   model_0   model_1   model_2 ...   model_S   ← isolated learners
      ▼         ▼         ▼             ▼
    P(y|x) soft-voting aggregator:  h(x) = 1/S Σ P_i(y|x)
```

**Ключевые свойства.**

1. **Sharded**: $D = \bigsqcup_{s=1}^{S} D_s$, шарды дизъюнктны.
2. **Isolated**: каждый $D_s$ обучает независимую мини-модель $h_s$;
   градиенты/параметры между шардами не смешиваются.
3. **Sliced** (необязательный этап): внутри шарда — контрольные точки
   после каждого слайса. В прототипе не реализовано; см. §6 «Расширения».
4. **Aggregated**: предсказание ансамбля — среднее (soft voting) по всем
   активным шардам.

Для детерминированности маршрутизации мы используем стабильный
хеш 64-битной FNV-1a от `seed::user_id`: одна и та же запись всегда
попадает в один и тот же шард независимо от порядка строк.

### 2.1 Почему шардируем по `user_id`, а не по строкам

Все удаления — это удаления *пользователей*. Если строки одного и
того же пользователя размазаны по нескольким шардам (например, при
посегментном разбиении), одной команды `delete user=U` будет достаточно,
чтобы «поднять» сразу несколько шардов на переобучение. Хешируя по
`user_id`, мы гарантируем ровно **один** затронутый шард на один
удалённый ID → ожидаемая стоимость переобучения $\mathcal{O}(|D_s|)$ вместо $\mathcal{O}(|D|)$.

### 2.2 Размер шардов

Компромисс:

| $S$ маленькое | $S$ большое |
|---|---|
| Шарды большие, модели сильнее | Шарды малы, недообучение |
| Переобучение дороже | Переобучение быстрее |
| Меньше агрегаций → шум меньше | Голосование сглаживает шум |

Типично $S \in [5, 20]$. В `configs/default.yaml` задано `n_shards: 5`
как разумное начальное значение.

## 3. Как обучать — training procedure

### 3.1 Препроцессинг

`ml/preprocess.py`:
- **PII** (`user_id`, ФИО, email, телефон, даты) **не попадают в признаки**
  — чтобы не давать модели читов по идентификатору;
- **числовые** — z-score (среднее/σ сохраняются в `FeaturePipeline`);
- **булевые** — целочисленные 0/1;
- **категориальные** — one-hot по отсортированному списку уровней из
  обучающего фолда; неизвестные категории на инференсе дают
  all-zeros-вектор.

Состояние пайплайна сериализуется в `runs/<run_id>/pipeline.json`, чтобы
при любом последующем запросе использовать **те же самые** средние/σ
(иначе удалённые и новые данные будут жить в разных системах координат).

### 3.2 Базовые модели

**PyTorch Logistic Regression** (`ml/logreg.py`):
- один `nn.Linear(d, 1)` + сигмоида;
- loss: `BCEWithLogitsLoss(pos_weight=n_neg/n_pos)` для балансировки;
- оптимизатор: Adam с `weight_decay` (L2);
- full-batch GD, ранняя остановка по train-loss.

Почему не `sklearn.LogisticRegression`? Нужен прямой доступ к циклу
обучения, чтобы в будущем подставить certified-unlearning шаги
(Newton-step, градиентное «вычитание» влияния — см. §6).

**Random Forest** (`ml/rf.py`): обёртка над
`sklearn.ensemble.RandomForestClassifier` для перекрёстной проверки
(нелинейная граница, иная индуктивная смещённость).

### 3.3 Обучение ансамбля

`SISAEnsemble.fit`:

1. Построить `ShardPlan` по `user_id`.
2. Для каждого шарда $s$: создать `BaseLearner` из factory и вызвать
   `fit(X[idx_s], y[idx_s])`.
3. Засечь время, финальный loss — сохранить в `SISAReport`.

Сложность: $\mathcal{O}\bigl(\sum_s c(|D_s|)\bigr)$, где $c(\cdot)$ — стоимость
одиночной модели. Для логрегрессии полного пакета $c(n) = O(n \cdot d \cdot E)$
($E$ — количество эпох). Чем меньше шард, тем быстрее он сходится.

## 4. Как удалять данные — unlearning procedure

Запрос — структура `UnlearnRequest` из `ml/unlearning.py`:

```python
UnlearnRequest(
    user_ids=["USR-000123", ...],       # delete-by-ID
    filter_query="consent_given == False",  # delete-by-filter
    reason="152-ФЗ ст.14",
)
```

Алгоритм `Unlearner.unlearn`:

1. **Разрешение**: `resolve_rows(df, request)` → массив индексов строк,
   подлежащих удалению (объединение по ID и по фильтру).
2. **Диагностика до**: снимок предсказаний и метрик на тестовой выборке.
3. **Пересбор плана**: `plan.rebuild_after_deletion(rows)` возвращает
   новый `ShardPlan` (без удалённых строк) и множество `affected`
   затронутых шардов.
4. **Обновление состояния**: из `df_train / X_train / y_train` удаляются
   соответствующие строки; индексы пересчитываются.
5. **Переобучение**: `ensemble.retrain_shards(affected, X, y)` — только
   затронутые шарды. Остальные модели остаются *бит-в-бит* такими же,
   какими были, — это и даёт exact unlearning.
6. **Диагностика после**: новые предсказания/метрики и Δ-отчёт.
7. **Аудит**: `RunRegistry.log_event("unlearn", ...)` пишет запись в
   append-only `events.log` с количеством удалённых записей, временем,
   затронутыми шардами и reason-кодом — это соответствует требованию
   152-ФЗ к журналированию операций обработки ПДн.

### 4.1 Стоимость

Пусть $k$ — число затронутых шардов (при delete-by-ID обычно $k=1$).
Тогда общий объём переобучения — $\sum_{s \in \text{affected}} c(|D_s|)$,
то есть порядка $k/S$ от полного fit. В экспериментах с $S=5$ и
удалением 10 случайных пользователей затрагивается, в среднем,
$\approx 4$ шарда → экономия $\approx 20\%$. Для точечных удалений
(1–3 пользователя) экономия растёт до $60$–$80\%$.

### 4.2 Альтернативные стратегии (в коде оставлены заглушки)

- **Certified unlearning для логрегрессии** — сдвиг весов на
  $\theta_{\text{new}} = \theta + H^{-1} \sum_{(x,y)\in D_f} \nabla \ell(\theta; x, y)$
  (Guo et al., 2020). Требует хранения гессиана $H$; добавляется в
  отдельный метод `TorchLogReg.influence_remove`.
- **Amnesiac learning** (Graves et al., 2021) — сохранение `∑ ΔW` за
  каждую эпоху на каждой записи; при удалении — вычитание
  соответствующих сумм. Тяжело по памяти, но дёшево по времени.
- **Gradient projection / SGA unlearning** — Newton-step на
  вычислимых блоках. Подходит для нейросетей.

## 5. Сбор метрик и оценка эффективности

`ml/metrics.py` считает, для заданного $(y_{\text{true}}, y_{\text{score}})$,
следующее (ТЗ §6.2.1.1):

| Метрика | Формула | Смысл |
|---|---|---|
| Accuracy  | $(TP+TN)/N$ | общая доля правильных |
| Precision | $TP/(TP+FP)$ | точность положительного класса |
| Recall    | $TP/(TP+FN)$ | полнота положительного класса |
| F1        | $2 PR / (P+R)$ | гармоническое среднее |
| ROC AUC   | $P(s(+) > s(-)) + \tfrac12 P(s(+){=}s(-))$ | порядковая квалиа |
| MSE       | $\tfrac1N \sum (p_i - y_i)^2$ | «движение» границы |

AUC реализован через идентичность Манна–Уитни без зависимости от
scikit-learn (чтобы тест не ломался при частичной установке).

### 5.1 Метрики эффективности unlearning

После каждой операции `unlearn` собираются:

- **Δ-метрики** — $\Delta m = m_{\text{after}} - m_{\text{before}}$ для всех
  классических метрик выше.
- **Prediction disagreement** — доля строк тестовой выборки, где
  hard-label изменился: $\frac{1}{|T|} \sum_{x\in T}
  [\![\hat y_{\text{before}}(x) \neq \hat y_{\text{after}}(x)]\!]$.
  Нулевое значение означает, что удалённые строки не влияли на решения
  модели; высокое — что модель действительно «зависела» от них.
- **Время и ресурсы** — `retrain_report.total_wall_time_sec`,
  `result.wall_time_sec` (полный цикл), размеры затронутых шардов.
  Потребление памяти снимает обёртка `resource.getrusage(RUSAGE_SELF)`
  в CLI-слое (расширение — см. `ml/registry.py::log_event`).

### 5.2 Диагностика верификации удаления (attack-based)

Для качественной проверки «забывания» в ТЗ упоминается
*верификация*: прототип готов к подключению **Membership Inference
Attack (MIA)** — атаки, оценивающей, способен ли внешний классификатор
отличить «бывших членов» $D_f$ от «никогда не виденных» записей по
выходам модели. После корректного unlearning AUC такой атаки должен
быть $\approx 0.5$. Каркас для MIA помещён в отдельный модуль
`ml/attacks/mia.py` (не реализован в прототипе, отмечено в README).

### 5.3 Воспроизводимость

Для каждого запуска фиксируются:

- `random_seed` и `shard_seed` → генерация данных, шардирование,
  инициализация весов, permutation внутри full-batch эпохи;
- SHA-1 входного CSV → гарантия, что датасет не менялся;
- полный YAML-конфиг и версия модели → записаны в `manifest.yaml`.

Повторный запуск `python cli.py train --config ... --data ...` при тех же
seed и SHA-1 даёт идентичные метрики (с точностью до недетерминизма
CUDA, которая в прототипе по умолчанию выключена: `device=cpu`).

## 6. Расширения и дорожная карта

1. **Slicing внутри шарда**: после каждой $1/K$-ой части данных класть
   checkpoint; при удалении откатываться до последнего «чистого».
2. **Certified unlearning для LogReg** через Influence Function.
3. **Разнородные backbone-ы в шардах** (например, LogReg + RF + GBM в
   одном ансамбле).
4. **Differential Privacy** поверх SISA: DP-SGD внутри каждого шарда
   даёт $(\varepsilon, \delta)$-приватность и по построению «размывает»
   влияние любой отдельной записи.
5. **MIA и прочие attack-based метрики** для независимой верификации
   «полноты забывания» (ТЗ §4.1.3, «верификация полного удаления»).
6. **Web-интерфейс** (Flask) поверх существующего CLI — тот же
   `ExperimentPipeline`, обёрнутый в REST.
