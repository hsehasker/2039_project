# Документация для разработчиков: Интеграция `panel.py`

## Обзор
`panel.py` служит центральным скриптом оркестрации (CLI Панелью) для проекта 2039 ("Механизмы цифрового забвения"). Он объединяет две основные подсистемы:
1. `synthetic_data_generator` (Генерация данных)
2. `unlearning_system` (Машинное разобучение SISA)

Панель реализует интерактивный цикл Read-Eval-Print Loop (REPL) с использованием стандартного ввода-вывода Python, что устраняет необходимость в тяжелом веб-фреймворке. Все состояние проходит через объект `PanelState` в оперативной памяти, что означает, что взаимодействия локализованы в одной легковесной сессии.

## Архитектура и интеграция

### Работа с путями (Path Manipulation)
Чтобы обеспечить возможность разрешения локальных подпакетов (`generator` и `ml`) без необходимости выполнения пользователем команды `pip install -e .` в обеих директориях, `panel.py` явно изменяет `sys.path` при запуске:
```python
PROJECT_ROOT = Path(__file__).resolve().parent
GEN_DIR = PROJECT_ROOT / "synthetic_data_generator"
UNL_DIR = PROJECT_ROOT / "unlearning_system"

sys.path.insert(0, str(UNL_DIR))
sys.path.insert(0, str(GEN_DIR))
```

### Управление состоянием (State Management): `PanelState`
`PanelState` определен как `dataclass` и служит контейнером изменяемого состояния, передаваемым непосредственно в обработчики действий.
- **Управление конфигурацией**: Отслеживает пути к `gen_config` и `unl_config`.
- **Отслеживание артефактов**: Содержит `dataset_path` (текущий активный CSV) и `run_dir`/`run_id` (снимок текущей ML-оценки).
- **Объекты в памяти**: Сохраняет ленивую ссылку на экземпляр `ExperimentPipeline` и его отчет `baseline`. Если конфигурация или датасет меняются, эти ссылки обнуляются (`None`), что заставляет систему выполнить повторное обучение (re-train).
- **Журнал аудита (Audit Logging)**: Ведет хронологический список действий в `state.events` для записи в сессионные логи.

## Основной цикл и Диспетчер (Core Loop & Dispatcher)
Приложение запускает бесконечный цикл `while True`, который:
1. Очищает экран (по желанию).
2. Выводит текущее состояние сессии с помощью `state.as_lines()`.
3. Отображает меню команд.
4. Ожидает ввода.
5. Выполняет соответствующую функцию `action_*` на основе ввода пользователя.

Весь ввод проходит через функции-обертки для валидации (`ask_int`, `ask_bool`, `ask`), предотвращая сбои из-за неверных типов (например, `ValueError` при конвертации строки в число).

## Обработчики действий (Action Handlers)
Логика операций разделена на функции с единственной ответственностью.

1. **`action_generate(state: PanelState)`**: 
   - Временно изменяет текущую рабочую директорию (`os.chdir(GEN_DIR)`), чтобы убедиться, что любые относительные пути, создаваемые генератором, попадают в правильную папку `synthetic_data_generator/data`.
   - Инстанцирует `SyntheticDataGenerator`, запускает генерацию, валидацию и сохраняет CSV.
   - Сбрасывает кешированные ссылки ML-пайплайна.
   
2. **`action_validate(state: PanelState)`** и **`action_info(state: PanelState)`**:
   - Читают датасет напрямую через `pandas`, выводя структуру и статистические границы. Не изменяют ML-кеш в `PanelState`.

3. **`action_train(state: PanelState)`** (из системы UNL):
   - Инициализирует новый `ExperimentPipeline`, используя метрики конфигурации.
   - Обучает модель на данных, присваивает `state.pipeline` и кеширует обученные базовые (baseline) метрики.

4. **`action_unlearn(state: PanelState)`** (По ID/Фильтру):
   - Передает запрос в функцию `pipeline.unlearn()`.
   - Измеряет деградацию метрик ($\Delta$) через точные определения в `ml/metrics.py`.

## Обработка ошибок и логирование (Exception Handling & Logging)
- **Локальные логи**: Каждая сессия запуска генерирует файл `panel_YYYYMMDDTHHMMSS.log` в корневой директории `logs/`, содержащий необработанные трассировки (tracebacks) и системные события.
- **Изящное восстановление после сбоев (Graceful Failure)**: Функции действий перехватывают базовое исключение `Exception`, выводят краткое описание с помощью `err()`, логируют полный traceback и совершают строгий `return`, что гарантирует, что цикл панели не упадет для пользователя.

## Добавление новых функций (Adding Features)
Чтобы реализовать новую функцию:
1. **Определите действие**: Напишите `def action_my_feature(state: PanelState) -> None:`
2. **Обработка контекста**: Убедитесь, что пути сохраняются с помощью `prev_cwd = os.getcwd()` и сбрасываются в блоке `finally`, если вы затрагиваете поддиректории.
3. **Опция меню**: Добавьте индекс/алиас в словарь диспетчеризации `MENU`, направляющий к `action_my_feature`.
4. **Обновление состояния**: Аккуратно верните изменения артефактов в `PanelState`.
