## 2. Глубокое погружение в Generator (`synthetic_data_generator`)

### 2.1 Математика генерации
За математическое распределение отвечают модули `distributions.py` и `correlations.py`.
Вместо использования псевдо-случайных функций без ограничений, генератор гарантирует академическую точность на базе библиотеки `numpy.random.Generator`.
* **Доступные распределения**: Нормальное (`normal`), логнормальное (`lognormal` - оптимизировано для генерации финансовых признаков `purchase_amount`), экспоненциальное (`exponential`), Бернулли (`bernoulli`).
* **Корреляции**: Регулируются матрицами связей. Поддерживается введение положительной/отрицательной ковариации до начала применения функции Labeler.

### 2.2 Модуль разметки (`labeler.py`)
ТЗ (п. 4.2) требует гибкой системы меток. В коде реализованы 2 стратегии:
1. **Rule-based (Детерминированная)**: Метка (`label = 1`) ставится строго, если `consent_given == False` или `deletion_requested == True`. Задает идеальное бинарное дерево.
2. **Probabilistic (Теоретико-вероятностная)**: Симулирует реальный мир. Признаки складываются с весами (скоринг), пропускаются через логистическую функцию (сигмоиду) $P(y=1) = \frac{1}{1 + e^{-(score - threshold)}}$. Значение конвертируется в таргет с добавлением белого шума.

## 3. Ядро Machine Unlearning: SISA Engine (`unlearning_system`)

Основа проекта — отказ от классического полного переобучения (Exact Unlearning via Retraining from Scratch). Мы реализовали академичный подход **SISA** (Bourtoule et al.).

### 3.1 Хеширование и маршрутизация (`shards.py`)
Функция `assign_shards` гарантирует **стабильность маршрутизации**. 
* Алгоритм переводит идентификатор пользователя `user_id` в детерминированный индекс шарда от $0$ до $K-1$.
* Формула маршрутизации: `shard_id = hash(user_id + seed) % n_shards`.
* Это гарантирует, что если мы остановим программу и запустим завтра, пользователь `U-001` попадет строго в тот же шард. 

### 3.2 Жизненный цикл ансамбля (`sisa.py`)
1. **`fit()`**: Данные фильтруются масками, каждый `BaseLearner` (модель шарда) обучается синхронно и независимо на своей порции $D_k \subset D$.
2. **`predict_proba()`**: Выход классификаторов объединяется через стратегию "Soft Voting". Вероятности $K$ моделей усредняются: $P(y=1) = \frac{1}{K}\sum^K_{i=1} P_i(y=1)$.
3. **`retrain_shards(affected_indices)`**: Если поступает запрос на удаление строк $D_u$, контроллер вычисляет пересечения индексов $D_u \cap D_k$. Вызывается `.fit()` **только у затронутых шардов**. Вычислительная сложность уменьшается в $K$ раз (если удаляемые пользователи лежали в 1 шарде из 5, мы экономим 80% серверного времени).

## 4. Фабрика ML Моделей (Model Abstract Factory)

Точка расширения системы — `BaseLearner` (`ml/base.py`). Любой алгоритм должен реализовать методы `fit`, `predict_proba` и `state_dict`. Это гарантирует полиморфизм интерфейсов.

### 4.1 Логистическая Регрессия (`ml/logreg.py`)
Написана "low-level" на **PyTorch** (`torch.nn.Linear`). 
* **Зачем**: PyTorch сохраняет графы вычислений и тензоры весов.
* **Функция потерь**: `BCEWithLogitsLoss`.
* Оптимизатор: SGD или Adam в сочетании с L2-регуляризацией (`weight_decay`).
* *Критическая фича*: Позволяет извлекать градиенты для метрики Verification Error.

### 4.2 Ансамблевые и древовидные модели (`ml/rf.py`, `ml/dt.py`)
Написаны с использованием **Scikit-Learn**.
* `RandomForestClassifier` и `DecisionTreeClassifier`. 
* **Зачем**: Удовлетворение требований ТЗ по поддержке деревьев решений. В обертке предусмотрено кэширование, сериализация через `pickle` / `joblib`. 
* *(Примечание: SVM и Gradient Boosting удалены из контура согласно ограничениям ТЗ)*.

## 5. Вычислитель метрик (`ml/metrics.py`)

Вычисление метрик — важнейший этап аудита (ТЗ §6.2.1.1).
* **Accuracy** и **AUC-ROC** используют стандартные функции `sklearn.metrics`.
* **F1-Мера**: Формула жестко прописана через точность и полноту.
  $$F1 = 2 \cdot \frac{Precision \times Recall}{Precision + Recall}$$
* **Verification Error (По Thudi et al.)**: Вычисляет дистанцию между параметрами модели:
  $L_2(W_{before}, W_{after}) = \sqrt{\sum (w_{before}^i - w_{after}^i)^2}$
  Данная метрика показывает, осталось ли в весах нейросети влияние извлеченных данных. Сильно ненулевой вектор дистанции после разобучения — индикатор успешного вмешательства в шард.

Обертка `ClassificationReport` перегружает магический метод `__sub__`, что позволяет нам вычислять $\Delta$ метрик простым вычитанием: `delta = report_after - report_before`.

## 6. Компонентный интерфейс (Оркестрация)

### 6.1 Единая панель состояния (`panel.py`)
Реализует **Stateful Pattern**. Объект `PanelState` (dataclass) держит все в ОЗУ:
* Избегает создания временных файлов (`pandas.DataFrame` лежит прямо в памяти).
* Если пользователь вызывает `unlearn_id U-123`, `PanelState.pipeline` заставляет `sisa.py` перестроить шарды, `PanelState.baseline` пересчитывает метрики, а в `state.events` попадает транзакция: `{"event": "unlearn", "user": "U-123", "delta_f1": -0.001}`.

### 6.2 REST API (`web_app.py`)
Реализует **Stateless Pattern**. 
* JSON Schemas строго типизированы: любой HTTP 400 или HTTP 500 вернется в формате `{"success": False, "error": "Текст ошибки"}`.

## 7. Журналирование и Q&A Тестирование

### 7.1 Аудит (JSON Registry)
Модуль `ml/registry.py` ведет логи по стандарту Append-Only-Log. 
Каждый эксперимент генерирует в папке `runs/<run_id>` файлы: 
1. `manifest.yaml` (Seed эксперимента, гиперпараметры, SHA-1 хеш датасета для контроля целостности и недопущения скрытой подмены данных).
2. `events.jsonl` (Лог "дозаписи" фактов удаления с таймстемпами).

### 7.2 Стратегия тестирования (`pytest`)
Для исключения регрессий в коде лежит 49 юнит- и E2E тестов.
* Тестируются распределения (нет ли дисбаланса Гаусса).
* Тестируется `assign_shards_is_deterministic`: гарантировано, что на разных машинах пользователи попадут в один шард.
* Тестируется независимость математики метрик (`test_metrics_match_independent_computation` в `test_smoke.py` сверяет выход системы со строгим долевым ручным математическим подсчетом).

## 8. Руководство по расширению (Extensibility / FAQ)

* **Как добавить новый ML Алгоритм?** 
  1. Создайте класс в `unlearning_system/ml/your_algo.py`.
  2. Унаследуйте его от `BaseLearner`. Реализуйте `.fit()` и `.predict_proba()`.
  3. В `BaseLearner.create()` добавьте `if config["backend"] == "your_algo": return YourAlgo()`.
* **Почему при удалении $L_2$ Verification Error равен нулю у Decision Tree?**
  Специфика деревьев в Scikit-Learn: они не оперируют весами слоев (тензорами), а строят структуру узлов (If-Else). Вычисление градиента для них математически некорректно, поэтому метрика `Verification Error` отключается или игнорируется, а аудит опирается на $\Delta F1$ и $\Delta Accuracy$. Для LogReg на PyTorch это работает без нареканий.
* **Как добавить новую фичу в генератор?**
  В `generator/configs/default.yaml` добавьте ключ в `features`, а в `synthetic_data_generator/generator/distributions.py` пропишите `elif type == 'your_type'`.
