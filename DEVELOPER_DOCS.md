# Инженерная документация комплекса (Developer Docs)
**Архитектура, принципы работы и интеграционные срезы**

Программный прототип реализован на стеке Python (PyTorch + Scikit-Learn + Pandas). Его задача — предоставить изолированную, надежную среду для тестирования алгоритмов Machine Unlearning на базе шардирования.

---

## 1. Диаграмма взаимодействия (`panel.py` / `web_app.py`)

Сердцем интеграции является модуль-фасад, оперирующий компонентами. Когда системный администратор вызывает `panel.py`, происходит следующее:
1. **Memory State:** Создается объект `PanelState` (dataclass). Он кэширует контексты: где лежат данные, какой ML-модели они принадлежат, и каковы последние метрики.
2. **Path Manipulation:** `panel.py` изменяет пути интерпретатора (sys.path), чтобы независимо разработанные папки `synthetic_data_generator` и `unlearning_system` могли импортировать друг друга (например, валидатору из одной папки нужен доступ к метрикам из другой).
3. **Cross-Component Events:** При вызове команды удалений через Консоль:
   * Модуль читает `dataset_path` из памяти.
   * `ExperimentPipeline` получает список `user_id`.
   * Он стучится в `ml/shards.py`, который хранит маппинг "Строка датасета" -> "Номер Шарда".
   * Обновляется датасет, переобучаются только $N$ изолированных шардов, а не все $K$.
   * В лог-файл (и на экран) выводится $\Delta$ метрик.

*Для веб-среды*: скрипт `web_app.py` поднимает локальный Flask-сервер (порт 5000), предоставляя REST API для кнопок фронтенда, расположенного в `templates/index.html`. В отличие от `panel.py` (который stateful, то есть хранит состояние в оперативной памяти между действиями), `web_app.py` спроектирован как stateless.

## 2. Программные интерфейсы алгоритмов SISA

Главная особенность технического задания проекта — поддержка определенных базисных моделей (Случайный лес, Дерево Решений, ЛогРегрессия). Обертка алгоритмов лежит в каталоге `unlearning_system/ml`.

### 2.1 Движок SISA (`sisa.py` и `shards.py`)
Обучение (метод `fit` в `sisa.py`) итерируется по подготовленному в `shards.py` словарю распределения пользователей (детерминированное хеширование по seed). Каждый шард — это отдельный объект `BaseLearner`.

При поступлении процедуры разобучения `retrain_shards()` на вход подаются измененные данные $D \setminus D_{u}$ (где $D_u$ — удаляемые строки). Движок "сбрасывает" память только тех экземпляров `BaseLearner`, которые содержали $D_u$.

### 2.2 Фабрика ML-моделей
Все алгоритмы реализуют строгий контракт (интерфейс `BaseLearner` из `base.py`), требующий наличия методов `.fit()`, `.predict_proba()` и `.state_dict()`:

* **LogReg Backend (`logreg.py`)**: Реализует логистическую регрессию через полносвязную нейросеть `torch.nn.Linear`. Позволяет вычислять градиенты и сравнивать `state_dict` (используется для метрики *Verification Error*, вычисляющей L2-дистанцию между весами до и после удаления данных).
* **Tree-based Backends (`rf.py`, `dt.py`)**: Обертки над `sklearn.ensemble.RandomForestClassifier` и `sklearn.tree.DecisionTreeClassifier`. Для них вычисление градиентного Verification Error невозможно, однако они демонстрируют отличные показатели F1/AUC.

Инстанцирование моделей осуществляется через класс `BaseLearner.create(config)`, который парсит `unlearning_system/configs/default.yaml` и вызывает нужный движок на основе ключа `model.backend`.

## 3. Математика метрик (`metrics.py`)

Оценка эффективности разобучения базируется на сравнении показателей "до" и "после" удаления. 

Функция `compute_classification_metrics(y_true, y_score)` применяет порог доверия $0.5$ к выводам `predict_proba`. Она вычисляет:
1. $Accuracy = \frac{TP+TN}{TP+TN+FP+FN}$
2. $Precision$
3. $Recall$
4. F1-меру строго через Precision и Recall.
5. $AUC$ (через `roc_auc_score` Scikit-learn).
Метрики инкапсулируются в объект `ClassificationReport`, который затем вычитается один из другого, создавая Дельты ($\Delta Accuracy$, $\Delta F1$), логируясь в `reports` как неоспоримое доказательство математической работы Machine Unlearning.
