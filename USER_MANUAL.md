# Подробное руководство пользователя и администратора
**Проект 2039: «Механизмы цифрового забвения»**

Настоящий документ является исчерпывающим руководством по эксплуатации программного комплекса. Он описывает процесс взаимодействия модулей, логику обработки данных и содержит подробную справочную информацию по конфигурационным файлам (YAML).

---

## 1. Взаимодействие компонентов системы

Архитектура прототипа спроектирована по модульному принципу. Главная цель проекта — обеспечить сквозной цикл (E2E) от создания синтетических данных до демонстрации полного спектра возможностей алгоритмов Machine Unlearning (SISA).

Система включает в себя следующие компоненты и их взаимодействия:

1. **Генератор данных (`synthetic_data_generator`)**:
   * Работает полностью независимо.
   * Принимает на вход YAML-конфиг (`generator/configs/default.yaml`) с описанием желаемых распределений, признаков (например, возраст, сумма покупок, регион) и корреляций между ними.
   * Выдает "на выход" файл `.csv` (или `.parquet`), в котором находятся табличные данные с целевой переменной `label` (подлежит удалению или нет, основываясь на согласии на обработку персональных данных).
   
2. **Ядро машинного разобучения (`unlearning_system`)**:
   * Ожидает на входе `.csv` файл, подготовленный генератором (или реальный дамп данных).
   * Инициализирует SISA-оркестратор: разбивает весь датасет на $K$ изолированных "шардов" с помощью детерминированного хеширования по `user_id`.
   * **Этап Train**: Обучает независимую модель в каждом шарде. Если шард "падает", переобучается только он.
   * **Этап Unlearn**: Получает запрос (`UnlearnRequest`) на удаление конкретных `user_id`. Контроллер системы мгновенно определяет, в какие шарды попали эти пользователи, и дает поручение переобучить *только их*, не затрагивая остальные.
   * **Метрики и логи**: Записывает историю работы (события обучения, изменения метрик "до" и "после") в JSONL-архив каталога `runs/`.

3. **CLI Панель оркестрации (`panel.py`)**:
   * Единая точка (REPL оболочка), объединяющая генератор и ML-подсистему в оперативной памяти.
   * Избавляет от необходимости копировать пути к файлам между консольными вызовами.

## 2. Написание и оформление YAML-конфигураций

Гибкость комплекса обеспечивается двумя главными конфигурационными файлами формата `.yaml`. Ниже приведена подробная инструкция по их настройке.

### 2.1. Конфигурация Генератора (`synthetic_data_generator/configs/default.yaml`)

Управляет количеством данных, типами признаков и их математическими распределениями.

```yaml
generator:
  n_samples: 10000            # Сколько строк (пользователей) сгенерировать
  random_seed: 42             # Фиксация зерна (seed) для воспроизводимости
  output_format: csv          # Поддерживаемый формат: csv или parquet
  output_path: data/synthetic_dataset.csv

features:
  # Блок идентификаторов (формируются текстом или датами)
  user_id:
    type: sequential_id
    prefix: "USR"             # Формат будет USR-000001, USR-000002
  birth_date:
    type: derived_from_age    # Дата рождения будет рассчитана на основе колонки age
  
  # Блок поведенческих и демографических признаков (задаются математически)
  age:
    distribution: normal      # Нормальное распределение
    mean: 35                  # Математическое ожидание
    std: 10                   # Стандартное отклонение
    clip: [18, 75]            # Ограничение по границам (от 18 до 75 лет)
  
  region:
    distribution: categorical # Категориальное распределение
    categories:               # Сумма вероятностей должна быть равна 1.0
      Moscow: 0.30
      SPb: 0.20
      Other: 0.50             

  purchase_amount:
    distribution: lognormal   # Логнормальное распределение (отлично для финансов)
    mean: 4.5
    std: 1.0

correlations:
  # Можно задать матрицу корреляций факторов
  purchase_amount_count: 0.5  # Положительная корреляция (больше покупок = выше общая сумма)

labeling:
  mode: rule                  # Режим разметки таргета. 'rule' (жесткая логика) или 'probabilistic' (через сигмоиду)
  target_column: label        # Название целевой колонки (таргета)
```

**Что сюда можно вписать:** 
Вы можете добавлять новые колонки в раздел `features`. Поддерживаемые распределения `distribution`: `normal`, `lognormal`, `exponential`, `bernoulli`, `categorical`. Параметр `clip: [min, max]` используется, чтобы откинуть статистические выбросы (например, возраст ниже 0 лет).

### 2.2. Конфигурация Machine Unlearning (`unlearning_system/configs/default.yaml`)

Настраивает логику шардирования, параметры ML-алгоритмов и подготовку (препроцессинг) датасета.

```yaml
experiment:
  run_root: runs              # Место, куда будут сохраняться модели и отчеты
  random_seed: 42
  test_size: 0.2              # Доля тестовой выборки (hold-out)

sharding:
  n_shards: 5                 # Количество SISA-шардов (10-20 для реальных Big Data систем)
  shard_seed: 42              # Стабильное зерно для хеширования пользователей по батчам

model:
  backend: logreg             # Выбор ML алгоритма: 'logreg', 'random_forest', 'decision_tree'
  
  # Настройки Логистической регрессии (PyTorch)
  logreg:
    lr: 0.05                  # Темп обучения (Learning Rate)
    weight_decay: 1.0e-4      # L2-регуляризация
    epochs: 200               # Количество эпох
    device: cpu               # 'cpu' или 'cuda'
    class_weight: balanced    # Балансировка при дисбалансе классов таргета
  
  # Настройки Случайного Леса (Scikit-Learn)
  random_forest:
    n_estimators: 100         # Количество деревьев в лесу
    max_depth: 12             # Максимальная глубина дерева

preprocessing:
  target_column: label
  numeric_features:           # Колонки для StandardScaler (здесь только числа)
    - age
    - purchase_amount
  categorical_features:       # Колонки для OneHotEncoder (строки)
    - region
```

**Что сюда можно вписать:**
В `model.backend` вы можете менять классификатор налету: впишите `random_forest`, если хотите проверить мощную агрегацию деревьев, или `decision_tree`. При добавлении новых колонок генератора, обязательно укажите их в блоке `preprocessing`, чтобы конвейер знал, как их масштабировать (категориальные через OHE, численные через StandardScaler).

## 3. Полный цикл работы своими руками

1. **Редактирование конфигов:** Откройте конфигурации. При необходимости измените `n_samples` в генераторе и `backend` в системе обучения.
2. **Генерация:**
   ```bash
   python synthetic_data_generator/main.py generate --config synthetic_data_generator/configs/default.yaml
   ```
3. **Обучение:**
   ```bash
   python unlearning_system/cli.py train --config unlearning_system/configs/default.yaml --data synthetic_data_generator/data/synthetic_dataset.csv
   ```
4. **Удаление и аудит метрик:**
   Удаление данных инициализируется командой `unlearn`. Вы можете передать в нее параметр `--filter` (SQL-подобный фильтр pandas), чтобы удалить всех, кто не давал согласия на обработку:
   ```bash
   python unlearning_system/cli.py unlearn \
       --config unlearning_system/configs/default.yaml \
       --data synthetic_data_generator/data/synthetic_dataset.csv \
       --filter "consent_given == False" \
       --reason "В рамках соответствия требованиям 152-ФЗ"
   ```
5. **Глубокий отчет:**
   ```bash
   python unlearning_system/cli.py report --run runs/<имя_сгенерированной_папки>
   ```
   В консоль выведется отчет, показывающий $\Delta$ Accuracy, Verification Error и время, сэкономленное архитектурой SISA (вместо переобучения всего ансамбля, были задеты только несколько шардов).

Для автоматизации всех шагов выше без указания путей к файлам — используйте команду `python panel.py` в корне проекта, чтобы взаимодействовать с панелью управления системой.
